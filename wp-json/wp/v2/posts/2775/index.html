This document outlines the procedures to be followed in the event of an outage affecting a QuickEasy Cloud Server <\/strong>hosted on the AWS EC2 platform.<\/strong> This Disaster Recovery<\/strong> (DR) plan <\/strong>aims to ensure the swift recovery of services to minimise downtime and data loss.<\/p>\n\n\n\n

Contact Information<\/p>\n\n\n\n

In the event that a cloud server (and the QuickEasy Application) becomes unavailable, the following personnel should be contacted immediately:<\/p>\n\n\n\n

    \n
  • Primary Contact: <\/strong>QuickEasy Helpdesk – helpdesk@quickeasysoftware.com<\/a> and info@quickeasysoftware.com<\/a>; +27 (0) 87 820 7272.<\/li>\n\n\n\n
  • Customer Service Manager:<\/strong> Alexis Ronne – alexis@quickeasysoftware.com<\/a><\/li>\n\n\n\n
  • Operations Manager:<\/strong> Robert Bateman – robert@quickeasysoftware.com<\/a><\/li>\n<\/ul>\n\n\n\n

    Recovery Procedures<\/p>\n\n\n\n

    Step 1: Outage Detection<\/strong><\/p>\n\n\n\n

      \n
    • On notification of a cloud server unavailability, the QuickEasy Helpdesk will attempt to connect to the server through various protocols and management tools. <\/li>\n\n\n\n
    • Should the cloud server still not be reachable, QuickEasy will monitor AWS EC2 alarms and alerts for any indications of an outage.<\/li>\n\n\n\n
    • In case of a critical outage, the QuickEasy Helpdesk will communicate with the customer on an estimated time to repair provided by AWS and with any options to remain operational.<\/li>\n<\/ul>\n\n\n\n

      Step 2: Data Restore<\/strong><\/p>\n\n\n\n

      Should there be a requirement to remain operational or move the cloud server instance to another AWS location, QuickEasy will: <\/p>\n\n\n\n

        \n
      • access the latest backup of the Database from the secondary storage site.<\/li>\n\n\n\n
      • restore the backup to a new EC2 instance in the same or alternative AWS region.<\/li>\n<\/ul>\n\n\n\n

        Step 3: Database Configuration<\/strong><\/p>\n\n\n\n

          \n
        • Configure the restored database with the necessary settings and parameters.<\/li>\n\n\n\n
        • Verify connectivity and access permissions for applications and users.<\/li>\n<\/ul>\n\n\n\n

          Step 4: Application Reconfiguration (if applicable)<\/strong><\/p>\n\n\n\n

            \n
          • Update application configurations to point to the newly restored server and QuickEasy application.<\/li>\n\n\n\n
          • Test application functionality to ensure seamless integration with the newly implemented server.<\/li>\n<\/ul>\n\n\n\n

            Step 5: Validation and Testing<\/strong><\/p>\n\n\n\n

              \n
            • Conduct thorough testing of the backups to ensure data integrity and functionality.<\/li>\n<\/ul>\n\n\n\n

              Step 6: Communication<\/strong><\/p>\n\n\n\n

                \n
              • Notify relevant stakeholders about the status of the recovery process and the expected recovery time of the original cloud server\/location.<\/li>\n\n\n\n
              • Provide regular updates until normal location\/service restoration is achieved.<\/li>\n<\/ul>\n\n\n\n

                Testing<\/p>\n\n\n\n

                  \n
                • QuickEasy performs regular testing of the DR procedures to validate our effectiveness and identify areas for improvement.<\/li>\n\n\n\n
                • QuickEasy documents the results of tests and updates the DR plan as required.<\/li>\n<\/ul>\n\n\n\n

                  Continuous Improvement<\/p>\n\n\n\n

                    \n
                  • QuickEasy reviews and updates the DR plan periodically to incorporate lessons learned from testing and real-world incidents.<\/li>\n\n\n\n
                  • QuickEasy stays informed about AWS’s best practices and new features that can enhance DR capabilities.<\/li>\n<\/ul>\n\n\n\n

                    Conclusion<\/p>\n\n\n\n

                    This DR plan outlines the procedures to be followed for the recovery of the QuickEasy application and database hosted on the AWS EC2 platform in the event of an outage. By following these steps, we are able to minimise downtime, ensuring the continuity of critical business operations in case of a prolonged AWS outage.<\/p>\n","protected":false},"excerpt":{"rendered":"

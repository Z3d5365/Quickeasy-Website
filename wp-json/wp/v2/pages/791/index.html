Templates and Design<\/h1>\n\t

QuickEasy Software allows you to create and update document templates. This module can be accessed from\u00a0Main Menu > Utilities > QuickEasy Form Designer<\/strong>.<\/p>\n

You can access the form designer under\u00a0User\u00a0Settings > Other Settings > QuickEasy Form Designer – Access Allowed<\/strong>.<\/p>\n

The QuickEasy Form Designer is a component that was created by\u00a0Digital Metaphors<\/a>.<\/p>\n

    Design<\/p>\n

    The principles of Design also apply to Template design. An easy way for you to remember the four most important principles of design is by way of the acronym\u00a0C.R.A.P.<\/strong><\/p>\n

      \n
    • Contrast<\/strong><\/li>\n
    • Repetition<\/strong><\/li>\n
    • Alignment<\/strong><\/li>\n
    • Proximity<\/strong><\/li>\n<\/ul>\n

      Images<\/strong><\/h2>\n

      Most Templates will include Images for company logos, diagrams, etc. The resolution of an image is measured in\u00a0dots per inch<\/strong>\u00a0abbreviated to\u00a0dpi.\u00a0<\/strong>\u00a0High resolution equals high quality but also equals large file size – so we need to find the correct balance of quality versus file size.<\/p>\n

      Ideally Images that are used on templates should be the lowest resolution required to produce the best quality on the printing device that will output the document. For home and office printers, this is\u00a0150dpi<\/strong>\u00a0or\u00a059dpc<\/strong>\u00a0(dots per cm) at final size – in other words, using images with a higher resolution will only increase the file size and not the output quality.<\/p>\n

      Tips and Tricks<\/strong><\/h2>\n

      This topic gives you useful tips and tricks for creating Document and Report Templates.<\/p>\n

      Multiple Columns<\/strong><\/h2>\n

      Multiple column Layouts can be created by using the\u00a0Report > Layout<\/strong>\u00a0properties combined with the\u00a0Detail Band > Generation<\/strong>\u00a0properties. Columns can be equal in size or different sizes and can be populated from top to bottom or from left to right. The\u00a0Report > ColumnPositions<\/strong>\u00a0property allows you to add custom starting points for each column.<\/p>\n

      Managing Page Breaks<\/strong><\/h2>\n

      Care must be taken to manage page breaks on Reports that could run into multiple pages. You need to ensure that relevant data is kept together and where necessary, headings are reprinted on subsequent pages. The properties that control how\u00a0data is displayed on page breaks include:<\/p>\n

        \n
      • ReprintOnOverFlow\u00a0<\/strong><\/li>\n
      • KeepTogether<\/strong><\/li>\n
      • ShiftRelativeTo<\/strong><\/li>\n<\/ul>\n

        Notes<\/strong><\/p>\n

        A\u00a0Title Band<\/strong>\u00a0can be used to display the Header on the first page of a document while a shortened\u00a0PageHeader Band<\/strong>\u00a0can display the Header on subsequent pages. Remember to uncheck the\u00a0PrintOnFirstPage<\/strong>\u00a0property on the\u00a0PageHeader Band<\/strong>;\u00a0Regions<\/strong>\u00a0are useful for grouping the components that need to be kept together.<\/p>\n

        Grouping<\/strong><\/h2>\n

        Functionality is provided\u00a0to Group on one or more of the fields in a DataPipeLine – eg. When creating a Template for a Report. Click on\u00a0Main Menu > Report > Groups…<\/strong>\u00a0to create a new Group or to change the settings on an existing Group. Group Header and Footer Bands will automatically be created for each Group.<\/p>\n

        A List followed by Detail Pages<\/strong><\/h2>\n

        At times it might be useful to print a list of items, followed by a detail page for each item. For example, you might want to print a list of Quotations, followed by a detailed Quote Letter for each item on the list.<\/p>\n

        Set the Report’s DataPipeline to the one that contains the List.<\/p>\n

        Add a SubReport for the List Page to the Title Band and set the\u00a0PrintBehavior = pbSection<\/strong>. Use the same DataPipeLine on this SubReport that was used on the Report.<\/p>\n

        Add a SubReport for the Detail Pages to the Detail Band of the Report and set the\u00a0PrintBehavior = pbSection<\/strong>. The DataPipeLine property on this SubReport must remain empty.<\/p>\n\t

        Components and Properties<\/h1>\n\t

        Every Component in the Form Designer has a number of Properties, including the Report, Bands, Sub-Reports, Regions and other visual elements. You can use Properties to determine the look and feel as well as the behaviour of Components. This topic covers the most commonly used Properties in the Form Designer.<\/p>\n

        Report<\/strong><\/h2>\n

        To view the Report Properties, click the icon in the top left where the rulers meet.<\/p>\n

          \n
        • DataPipeline<\/strong>\u00a0– The Detail Band will be repeated once for every record in the Data Pipeline linked to this Property.<\/li>\n
        • NoDataBehaviors<\/strong>\u00a0– These Properties determine what is displayed when the primary Data Pipeline has no records. The preferred setting is\u00a0ndBlankReport = True<\/strong>, with the other NoDataBehaviors Properties = False.<\/li>\n
        • Printer Setup<\/strong>\u00a0– When documents need to be output to specific printers, these Properties can be used to automatically select and configure a printer. Typically these settings need to be made\u00a0onsite.<\/li>\n
        • Units<\/strong>\u00a0–\u00a0utMillimeters<\/strong>\u00a0is the preferred setting. When creating templates that are printed on continuous forms, the height of the form should be set using\u00a0utInches<\/strong>, however.<\/li>\n<\/ul>\n

          Bands<\/strong><\/h2>\n

          The layout on a Template is determined by\u00a0Bands, each with their own properties and behaviours:<\/p>\n

            \n
          • Title<\/strong>\u00a0– This is printed once at the beginning of the document, and can also be used as a Cover Page.<\/li>\n
          • Header<\/strong>\u00a0– This is printed at the top of each page.<\/li>\n
          • Detail<\/strong>\u00a0– This is printed once for every record in the list.<\/li>\n
          • Footer<\/strong>\u00a0– This is printed at the bottom of each page.<\/li>\n
          • Summary<\/strong>\u00a0– This is printed at the end of the document, after the Detail Band ends.<\/li>\n<\/ul>\n
              \n
            • PrintHeight<\/strong>\u00a0– This sets whether a Band is Static (Fixed height) or Dynamic (Height changes according to content).<\/li>\n
            • Height<\/strong>\u00a0– This sets the Height of the Band in the Units of the Report. Only applicable to Static Bands.<\/li>\n
            • PrintOnFirstPage\/PrintOnLastPage<\/strong>\u00a0– This is applicable to Headers and Footers.<\/li>\n
            • BottomOffset<\/strong>\u00a0– This creates a space below the Band in the Units of the Report – ie. if Report is in mm, a BottomOffset = 3 will create a 3mm space.<\/li>\n
            • NewPage<\/strong>\u00a0– This is applicable to Title and Summary Bands – when checked a new page will be created for the Band. eg. a Cover Page for a Report.<\/li>\n
            • Background1\/Background2<\/strong>\u00a0– This is applicable to Detail Bands and used to create different backgrounds for alternate records. Use\u00a0Report > PrintSetup > Margins<\/strong>\u00a0to prevent the Backgrounds from printing to the edge of the Report.<\/li>\n
            • PrintCount<\/strong>\u00a0– This is applicable to the Detail Band. Set\u00a0PrintCount = 1<\/strong>\u00a0to limit the Report to one detail record per page.<\/li>\n<\/ul>\n

              Label \/ DBText<\/strong><\/h2>\n

              Used to display text, numbers and dates in a single line. Commonly used properties include:<\/p>\n

                \n
              • BlankWhenZero<\/strong>\u00a0– This is applicable to numeric fields only – zero values are not displayed.<\/li>\n
              • Transparent<\/strong>\u00a0– Only the text is displayed\u00a0– useful when placing on top of an Image<\/li>\n
              • Anchor<\/strong>\u00a0– This is used to anchor a component to the Top or Bottom of Dynamic Bands.<\/li>\n
              • AutoSize<\/strong>\u00a0– The size is set automatically according to the content (not recommended).<\/li>\n
              • Ellipsis<\/strong>\u00a0– When checked, an ‘…’ is drawn where the text is truncated.<\/li>\n
              • ReprintOnOverFlow<\/strong>\u00a0– This will cause the Label\/DBText\u00a0to be reprinted if the Region or Band in which it is contained is split over a page break.<\/li>\n
              • TextAlignment<\/strong>\u00a0– This sets the horizontal alignment of the text.<\/li>\n
              • VerticalAlignment<\/strong>\u00a0– This sets the vertical alignment of the text.<\/li>\n
              • DisplayFormat<\/strong> – Used to format Numerical and Date Fields – right-click component for shortcut to DisplayFormat selector. eg. Currency = R#,0.00; Date = mm\/dd\/yy; Count = 0 Items.<\/li>\n
              • Avoid using Autosize = True;<\/li>\n<\/ul>\n

                Memo\/(DB)RichText<\/strong><\/h2>\n

                These components are used to display text in multiple lines. The Memo component is used to display plain text and the RichText component is used to display rich text. Commonly used properties include:<\/p>\n

                  \n
                • BottomOffset<\/strong>\u00a0–\u00a0This creates a space below the Band in the Units of the Report – ie. if Report is in mm, BottomOffset = 3 will create a 3mm space below the Memo.<\/li>\n
                • ShiftRelativeTo<\/strong>\u00a0– This is used to\u00a0determine the Top (starting point) of the component based on how much a preceding component stretches. The preceding component is selected in this property.<\/li>\n
                • StretchWithParent<\/strong>\u00a0– The height will increase according to how the Parent (Band or Region) stretches.<\/li>\n
                • Stretch<\/strong>\u00a0– This determines whether the component will stretch to display all the content or remain at a static height.<\/li>\n<\/ul>\n

                  Image \/ DBImage<\/strong><\/h2>\n

                  Used to display images on a report. Following are some of the commonly used properties.<\/p>\n

                    \n
                  • Picture<\/strong>\u00a0– This is used to link an image to the non-data aware component.<\/li>\n
                  • GraphicType<\/strong>\u00a0– AutoDetect should work fine in most instances. For best results use .jpg or .png images that are no larger than 150dpi (59ppc) at final size.<\/li>\n
                  • Stretch<\/strong>\u00a0– This determines whether the component will stretch to display all the content or remain at a static height.<\/li>\n
                  • MaintainAspectRatio<\/strong>\u00a0– Keep this property checked to ensure the image is not distorted when the Picture size does not match the Image component’s size.<\/li>\n<\/ul>\n

                    Avoid setting the Transparent property = True – this might cause unexpected results when exporting the template to PDF;\u00a0Avoid using Autosize = True; Always set Report>PDF Settings>Scale Images = False;<\/p>\n

                    Lines<\/strong><\/h2>\n

                    Lines can be added to a Report to separate and group components and to create grids. Useful properties include:<\/p>\n

                      \n
                    • Position<\/strong>\u00a0– Top, Bottom, Left and Right.<\/li>\n
                    • Pen<\/strong>\u00a0– This sets the\u00a0Style (Solid, Dashes, Dots), Color, etc.<\/li>\n
                    • Style<\/strong>\u00a0– Single or Double.<\/li>\n
                    • Weight<\/strong>\u00a0– Ideally\u00a0set between 0.2 and 0.5mm – try to keep the weight consistent throughout the report.<\/li>\n<\/ul>\n

                      The Alignment, Distribution and Size tools are very useful when creating tables with Lines. The height and width of a Line does not affect how it will be displayed – the height and width must be set to the minimum that\u00a0enables\u00a0easy selection of the line.<\/p>\n

                      DBCalc<\/strong><\/h2>\n

                      This is used to create a summary of values displayed in the Detail Band.\u00a0The type of summary is set using\u00a0DBCalcType<\/strong>. Options include:\u00a0Sum, Max, Min, Average, Count<\/strong>.<\/p>\n

                      When a DBCalc is used to display a summary ahead of the Detail Band, the\u00a0LookAhead<\/strong>\u00a0property needs to be checked and the\u00a0Report>PassSetting<\/strong>\u00a0must be set to\u00a0psTwoPasses<\/strong>.<\/p>\n

                      System Variable<\/strong><\/p>\n

                      System variables are mostly used to show page numbers and the time and date a document was created. The most important properties are:<\/p>\n

                      VarType<\/strong><\/p>\n

                        \n
                      • vtPageSetDesc<\/strong>\u00a0– This creates a combination of page number and page count eg. Page 1 of 3<\/li>\n
                      • vtPrintDateTime<\/strong>\u00a0– This prints the date and time the document was created or printed.<\/li>\n<\/ul>\n

                        SubReport<\/strong><\/h2>\n

                        A SubReport is used to nest reports or to group multiple Reports into one Report. All the properties used for a Report (see above) also apply to a SubReport. And in addition, the following properties are commonly used:<\/p>\n

                          \n
                        • PrintBehavior<\/strong>:\n
                            \n
                          • pbChild<\/strong>\u00a0– This is used when the SubReport is placed in the Detail Band of a Report to create a sub-detail list linked to the base DataPipeline. In\u00a0pbChild<\/strong>\u00a0mode mode the Header and Footer Bands on the SubReport are not visible.<\/li>\n
                          • pbSection<\/strong>\u00a0–\u00a0This is used to create a new independent Sub-Report. A\u00a0pbSection<\/strong>\u00a0SubReport should be placed in the Title, Detail or Summary Bands.<\/li>\n<\/ul>\n<\/li>\n
                          • ParentWidth<\/strong>\u00a0– When checked, the width of the SubReport is equal to the Report width. Uncheck this setting to set the SubReport to a different width.<\/li>\n
                          • ParentPrinterSetup<\/strong>\u00a0– Uncheck this setting when the SubReport must print to a different printer.<\/li>\n
                          • KeepTogether<\/strong>\u00a0– This will prevent the contents in the SubReport to be split over multiple pages. Care must be taken to ensure that the contents of the SubReport won’t ever exceed a full page.<\/li>\n
                          • BottomOffset<\/strong>\u00a0– This creates a space below the SubReport in the Units of the Report – ie. if Report is in mm, \u00a0BottomOffset = 3 will create a 3mm space below the SubReport.<\/li>\n
                          • ShiftRelativeTo<\/strong>\u00a0–\u00a0This is used to\u00a0determine the Top (starting point) of the component based on how much a preceding component stretches. The preceding component is selected in this property.<\/li>\n
                          • StretchWithParent<\/strong>\u00a0– The height will increase according to how the Parent (Band or Region) stretches.<\/li>\n<\/ul>\n

                            When the SubReport PrintBehavior property is set to pbChild, the Visible Property on the SubReport Header and Footer Bands is unchecked. If the PrintBehavior property is changed to pbSection, the Header and Footer Visible properties need to be manually checked.<\/p>\n

                            Region<\/strong><\/h2>\n

                            A Region is used to group a number of components so that they move together in response to changes in other dynamic components. They are also useful for managing the behaviour of components when a Report runs into multiple pages. Commonly used properties include:<\/p>\n

                              \n
                            • Border<\/strong>\u00a0– By default a Region has a black border. To clear the border, set\u00a0Pen > Style = psClear<\/strong>.<\/li>\n
                            • KeepTogether<\/strong>\u00a0– This will prevent the contents in the Region to be split over multiple pages. Care must be taken to ensure that the contents of the Region won’t ever exceed a full page.<\/li>\n
                            • BottomOffset<\/strong>\u00a0–\u00a0Creates a space below the Region in the Units of the Report – ie. if Report is in mm, \u00a0BottomOffset = 3 will create a 3mm space below the Region.<\/li>\n
                            • ReprintOnOverFlow<\/strong>\u00a0– This will cause the contents of the Region to be reprinted if the Region is split over a page break.<\/li>\n
                            • ShiftRelativeTo<\/strong>\u00a0– Used to\u00a0determine the Top (starting point) of the component based on how much a preceding component stretches. The preceding component is selected in this property.<\/li>\n
                            • StretchWithParent<\/strong>\u00a0– The height will increase according to how the Parent Band stretches.<\/li>\n<\/ul>\n

                              Check the Report Tree to ensure components are nested in a Region and not just overlapping the Region.<\/p>\n\t

Templates and Design

QuickEasy Software allows you to create and update document templates. This module can be accessed from Main Menu > Utilities > QuickEasy Form Designer.

You can access the form designer under User Settings > Other Settings > QuickEasy Form Designer – Access Allowed.

The QuickEasy Form Designer is a component that was created by Digital Metaphors. A tutorial on how to use ReportBuilder can be downloaded — Learning ReportBuilder is a complete learning system designed to teach end users how to build a range of reports, including a 125-page PDF file, a stand-alone application complete with a database, and a help file.

QuickEasy Form Designer

The QuickEasy Form Designer provides the tools to create and update document templates. The interface consists of:

  • Main Menu — links to all the functions.
  • Design / Preview tabs — allows you to toggle between Design view and Preview.
  • Toolbars
  • Report Tree — displays all the components used on a template in a tree view.
  • Properties — displays the properties for the selected component.
  • Design Panel
  • Data Tree — displays a list of all the available Data Pipelines and their corresponding fields; fields can be dragged onto the design panel and are displayed according to the Layout tab settings.
  • Status Bar — displays information about the selected component and provides zoom functionality.

  • Images — Paint.NET
  • Vector Drawings — Inkscape

Design

The principles of Design also apply to Template design. An easy way to remember the four most important principles of design is by way of the acronym C.R.A.P.

  • Contrast
  • Repetition
  • Alignment
  • Proximity

The above is only a drop in the ocean of what's freely available online on C.R.A.P. design.

Images

Most templates will include images for company logos, diagrams, etc. The resolution of an image is measured in dots per inch, abbreviated to dpi. High resolution equals high quality but also equals large file size — so you need to find the correct balance of quality versus file size.

Ideally, images used on templates should be the lowest resolution required to produce the best quality on the printing device that will output the document. For home and office printers, this is 150dpi (59dpc) at final size — using images with a higher resolution will only increase file size, not output quality.

Free image editing software: Paint.NET. Free photo re-sizing software: FastStone Photo Resizer.

Tips and Tricks

Useful tips and tricks for creating document and report templates.

Multiple Columns

Multiple column layouts can be created by using the Report > Layout properties combined with the Detail Band > Generation properties. Columns can be equal in size or different sizes and can be populated from top to bottom or from left to right. The Report > ColumnPositions property allows you to add custom starting points for each column.

Managing Page Breaks

Care must be taken to manage page breaks on reports that could run into multiple pages — relevant data must be kept together and, where necessary, headings reprinted on subsequent pages. Properties that control this include:

  • ReprintOnOverFlow
  • KeepTogether
  • ShiftRelativeTo

Notes: a Title Band can display the header on the first page while a shortened PageHeader Band displays the header on subsequent pages — remember to uncheck PrintOnFirstPage on the PageHeader Band. Regions are useful for grouping components that need to be kept together.

Grouping

Functionality is provided to group on one or more fields in a DataPipeline — e.g. when creating a template for a report. Click Main Menu > Report > Groups… to create a new group or change an existing one. Group Header and Footer Bands are automatically created for each group.

A List followed by Detail Pages

At times it might be useful to print a list of items, followed by a detail page for each item — for example, a list of quotations followed by a detailed quote letter for each item on the list.

  • Set the Report's DataPipeline to the one that contains the list.
  • Add a SubReport for the list page to the Title Band and set PrintBehavior = pbSection, using the same DataPipeline as the Report.
  • Add a SubReport for the detail pages to the Detail Band and set PrintBehavior = pbSection — the DataPipeline property on this SubReport must remain empty.

Components and Properties

Every component in the Form Designer has a number of properties — including the Report, Bands, Sub-Reports, Regions and other visual elements — used to determine the look, feel and behaviour of components. This section covers the most commonly used properties in the Form Designer.

Report

To view the Report properties, click the icon in the top left where the rulers meet.

  • DataPipeline — the Detail Band repeats once for every record in the linked Data Pipeline.
  • NoDataBehaviors — determines what's displayed when the primary Data Pipeline has no records; the preferred setting is ndBlankReport = True, with other NoDataBehaviors = False.
  • Printer Setup — used to automatically select and configure a printer when documents must output to specific printers (typically set onsite).
  • Units — utMillimeters is preferred; for templates printed on continuous forms, set the form's height using utInches.

Bands

The layout of a template is determined by Bands, each with their own properties and behaviours:

  • Title — printed once at the beginning of the document; can also be used as a cover page.
  • Header — printed at the top of each page.
  • Detail — printed once for every record in the list.
  • Footer — printed at the bottom of each page.
  • Summary — printed at the end of the document, after the Detail Band ends.
  • PrintHeight — sets whether a Band is Static (fixed height) or Dynamic (height changes with content).
  • Height — sets the height of the Band in the report's units (Static Bands only).
  • PrintOnFirstPage / PrintOnLastPage — applies to Headers and Footers.
  • BottomOffset — creates a space below the Band in the report's units (e.g. 3 = 3mm if the report is in mm).
  • NewPage — applies to Title and Summary Bands; when checked, a new page is created for the Band (e.g. a cover page for a report).
  • Background1 / Background2 — applies to Detail Bands, used to create different backgrounds for alternate records (use Report > PrintSetup > Margins to prevent backgrounds printing to the report edge).
  • PrintCount — applies to the Detail Band; set to 1 to limit the report to one detail record per page.

Label / DBText

Used to display text, numbers and dates in a single line. Commonly used properties:

  • BlankWhenZero — numeric fields only; zero values are not displayed.
  • Transparent — only the text is displayed, useful when placed on top of an image.
  • Anchor — anchors a component to the top or bottom of Dynamic Bands.
  • AutoSize — size is set automatically according to content (not recommended).
  • Ellipsis — when checked, an "…" is drawn where the text is truncated.
  • ReprintOnOverFlow — reprints the Label/DBText if the Region or Band it's in is split over a page break.
  • TextAlignment — horizontal text alignment.
  • VerticalAlignment — vertical text alignment.
  • DisplayFormat — formats numerical and date fields (right-click a component for the DisplayFormat selector), e.g. Currency = R#,0.00; Date = mm/dd/yy; Count = 0 Items.
  • Avoid using AutoSize = True.

Memo / (DB)RichText

Used to display text over multiple lines — Memo for plain text, RichText for rich text. Commonly used properties:

  • BottomOffset — space below the Memo in the report's units.
  • ShiftRelativeTo — determines the component's top (starting point) based on how much a preceding component stretches.
  • StretchWithParent — height increases according to how the parent (Band or Region) stretches.
  • Stretch — whether the component stretches to display all content or remains a static height.

Image / DBImage

Used to display images on a report. Commonly used properties:

  • Picture — links an image to the non-data-aware component.
  • GraphicType — AutoDetect works fine in most instances; use .jpg or .png images no larger than 150dpi (59ppc) at final size.
  • Stretch — whether the component stretches to display all content or remains a static height.
  • MaintainAspectRatio — keep checked so the image isn't distorted when the picture size doesn't match the component size.

Avoid setting Transparent = True (can cause unexpected results exporting to PDF); avoid AutoSize = True; always set Report > PDF Settings > Scale Images = False.

Lines

Lines can be added to separate and group components and to create grids. Useful properties:

  • Position — Top, Bottom, Left and Right.
  • Pen — sets the style (Solid, Dashes, Dots), colour, etc.
  • Style — Single or Double.
  • Weight — ideally between 0.2 and 0.5mm; keep it consistent throughout the report.

The Alignment, Distribution and Size tools are very useful when creating tables with lines. A line's height and width don't affect how it displays — set them to the minimum needed for easy selection.

DBCalc

Used to create a summary of values displayed in the Detail Band — the summary type is set using DBCalcType (Sum, Max, Min, Average, Count). When a DBCalc displays a summary ahead of the Detail Band, LookAhead must be checked and Report > PassSetting set to psTwoPasses.

System Variable

System variables are mostly used to show page numbers and the time/date a document was created. The most important property is VarType:

  • vtPageSetDesc — combines page number and page count, e.g. "Page 1 of 3".
  • vtPrintDateTime — prints the date and time the document was created or printed.

SubReport

Used to nest reports or group multiple reports into one. All properties used for a Report also apply to a SubReport, plus:

  • PrintBehavior: pbChild — used when the SubReport is placed in a Report's Detail Band to create a sub-detail list linked to the base DataPipeline; in pbChild mode, the Header and Footer Bands on the SubReport are not visible.
  • pbSection — creates a new independent Sub-Report, placed in the Title, Detail or Summary Bands.
  • ParentWidth — when checked, the SubReport width equals the Report width; uncheck to set a different width.
  • ParentPrinterSetup — uncheck when the SubReport must print to a different printer.
  • KeepTogether — prevents the SubReport's contents from splitting over multiple pages (take care the contents never exceed a full page).
  • BottomOffset — space below the SubReport in the report's units.
  • ShiftRelativeTo — determines the component's top (starting point) based on a preceding component's stretch.
  • StretchWithParent — height increases according to how the parent stretches.

When PrintBehavior is pbChild, the Visible property on the SubReport Header and Footer Bands is unchecked; if changed to pbSection, the Header/Footer Visible properties need to be manually checked.

Region

A Region groups components so they move together in response to changes in other dynamic components, and helps manage behaviour when a report runs into multiple pages. Commonly used properties:

  • Border — by default a Region has a black border; set Pen > Style = psClear to remove it.
  • KeepTogether — prevents the Region's contents from splitting over multiple pages (ensure contents never exceed a full page).
  • BottomOffset — space below the Region in the report's units.
  • ReprintOnOverFlow — reprints the Region's contents if it's split over a page break.
  • ShiftRelativeTo — determines the component's top (starting point) based on a preceding component's stretch.
  • StretchWithParent — height increases according to how the parent Band stretches.

Check the Report Tree to ensure components are nested in a Region and not just overlapping it.

Data Pipelines

You use Data Pipelines to access data that needs to be displayed on the document — they connect the template to the QuickEasy database. Data Pipelines can be viewed in the Data Tree in the top right of the Form Designer, grouped according to module.

Each Data Pipeline contains a list of fields, displayed in the panel below the Data Tree, which can be dragged directly onto a template.

We recommend always previewing a template, in the module it was created for, before opening the Form Designer — this ensures all Data Pipelines and their fields are visible in the Data Tree.
